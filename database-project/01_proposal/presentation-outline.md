# 1차 발표 구성안 (10분)

## 발표 목표

교수님께 “단순 주식 정보 조회 서비스가 아니라, 데이터 간 관계와 실제 업무 흐름이 분명한 DB 프로젝트”라는 점을 전달한다. 1차에서는 최종 설계를 단정하기보다, 왜 이 문제를 선택했고 어떤 데이터와 기능이 연결되는지 명확히 보여준다.

## 60초 서비스 소개 스크립트

“제가 기획한 서비스는 Stock Compass입니다. 개인 투자자는 기업 재무, 뉴스, 실적 일정, 자신의 투자 메모를 여러 곳에서 확인해야 합니다. 그래서 시간이 지나면 왜 그 기업을 골랐는지, 당시 판단이 맞았는지 되돌아보기 어렵습니다. Stock Compass는 기업 정보뿐 아니라 관심목록, 가상 포트폴리오, 거래 기록, 투자 가설과 근거를 연결해 사용자의 투자 판단 과정을 관리합니다. 실제 매매를 추천하는 서비스가 아니라, 데이터를 비교하고 자신의 판단을 기록·검증할 수 있게 하는 기업 투자 리서치 도구입니다.”

## 데이터 구조 설명 스크립트

“데이터는 크게 기업 데이터와 사용자 활동 데이터로 나뉩니다. 기업은 산업에 속하고 재무 보고서, 가격, 이벤트와 1:N 관계를 가집니다. 뉴스는 하나의 기사가 여러 기업에 관련될 수 있으므로 기업-뉴스 사이에 연결 테이블을 둡니다. 사용자도 여러 관심목록과 포트폴리오를 가질 수 있습니다. 관심목록과 기업은 N:M 관계이므로 항목 테이블로 해소하고, 가상 거래가 등록되면 거래 이력과 현재 보유 정보가 함께 관리됩니다. 이 구조를 통해 사용자별 화면과 기업별 분석 화면을 모두 만들 수 있습니다.”

## 발표 팁

- 테이블을 전부 외우려 하기보다 “기업 데이터”와 “사용자 활동 데이터”라는 두 묶음으로 설명한다.
- 아직 초안인 부분은 “2차에서 화면 요구사항을 확정한 뒤 검증하겠다”고 분명히 말한다.
- AI를 핵심 기능으로 과장하지 않는다. “AI는 저장된 데이터를 읽기 쉽게 요약하는 보조 기능”이라고 설명한다.
- 수익률이나 추천 정확성보다, 데이터 정합성·기록·비교·복기라는 DB 프로젝트의 가치를 강조한다.
